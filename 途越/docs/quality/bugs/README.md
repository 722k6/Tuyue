# 缺陷记录目录

测试阶段发现的缺陷统一放在本目录，一个缺陷一个文件。

## 命名

```
BUG-<模块>-<序号>-<问题简述>.md
```

示例：`BUG-CAR10-01-筛选无结果空态文案误导.md`。

编号与 `docs/quality/test-cases/测试用例及跟踪-<姓名>.xlsx` 的 BugID 列保持一致。

## 文件结构

按《开发规范》4.3 提交格式填写：

| 字段 | 要求 |
| ---- | ---- |
| BUG 编号 | `BUG-<模块>-<序号>` |
| 标题 | 「[模块] 一句话描述问题」 |
| 严重级别 | S0 / S1 / S2 / S3，定义见开发规范 4.2 |
| 所属模块 | 见用例模块清单 |
| 环境 | 浏览器、系统、测试账号、被测版本 |
| 复现步骤 | 编号列出，确保他人可独立复现 |
| 预期结果 | 正常应有的表现 |
| 实际结果 | 实际发生的表现 |
| 复现概率 | 必现 / 偶现（附概率） |
| 截图/录屏 | 可选，强烈建议 |

## 约定

- 一个文件只描述一个缺陷，禁止多问题合并。
- 已修复的缺陷回填「修复版本」与「验证结果」，同步更新 xlsx 中对应用例结果。
- S0/S1 缺陷需第一时间同步负责人。
- 提交方式与其他文档一致：分支 + PR，至少 1 人评审后合并。
