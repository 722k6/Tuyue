# 测试用例目录

小组按用户故事提交测试用例，统一放在本目录。**一个用户故事一个文件**，编写者为本故事的测试人员（见 `docs/Sprint3团队分工任务书.xlsx` 的「测试人员」列）。

## 命名

```
US-<模块>-<编号>-<故事简称>.md
```

示例：`US-CAR-12-车型参数管理.md`、`US-CAR-03-筛选与排序.md`。

用例编号沿用故事编号，序号三位递增：`CAR12-01`、`CAR12-02`；跨故事用例在故事内单独编号，不共用。

## 文件结构

每个文件包含三部分，模板见 [_template.md](./_template.md)：

1. **基本信息**——故事编号、负责人、测试人、测试日期、被测版本（分支/PR）。
2. **前置条件与测试数据**——启动方式、账号、稳定 Mock ID。
3. **用例表**——每行一条可执行用例：

| 列         | 要求                                         |
| ---------- | -------------------------------------------- |
| 用例编号   | 故事内唯一，如 `CAR12-03`                    |
| 优先级     | P0 阻塞 / P1 核心 / P2 一般                  |
| 前置条件   | 必要的状态与数据，能复现即可                 |
| 操作步骤   | 编号步骤，写明点击/输入/请求内容             |
| 预期结果   | 可判定的结果；接口用例写状态码 + 错误码      |
| 自动化脚本 | 有则填文件路径；没有写「手工」               |
| 执行结果   | 通过 / 不通过 / 阻塞 / 未执行                |
| 缺陷编号   | 不通过时填 `BUG-<故事>-<序号>`，并在文末汇总 |

约定：

- 预期结果只写**验收要点**，不写实现细节（例如写「缺失值渲染为 —」，不写组件名）。
- 接口用例必须覆盖成功路径、字段校验失败、资源不存在三类。
- 页面用例写清选择器无关的操作描述，便于别人手工复现。
- 执行结果如实填写；未开发完的故事先提交用例，标记「阻塞」，不要伪造通过。

## 提交方式

测试用例属于文档改动，同样走分支 + PR：

```bash
git checkout main && git pull
git checkout -b feature/test-cases-<你的名字>
# 新增 docs/quality/test-cases/US-XXX-NN-xxx.md
git add docs/quality/test-cases
git commit -m "docs: 补充 US-XXX 测试用例"
git push -u origin feature/test-cases-<你的名字>
```

在 GitHub 开 PR，至少 1 人评审后合并。执行记录（通过/不通过/缺陷）继续放在 `docs/quality/test-records/`，本目录只放用例本身。
