# 测试用例目录

小组按用户故事提交测试用例，统一放在本目录，提交格式为老师给定的 Excel 模板。

## 提交文件

| 文件 | 用途 |
| ---- | ---- |
| `途越测试用例及跟踪.xlsx` | **正式提交物**，全组共用一个文件，按模块分 sheet |
| `US-<模块>-<编号>-<故事简称>.md` | 可选的详细记录（含前置条件、缺陷分析），便于复现，不替代 xlsx |

Excel 结构：

- `需求列表` sheet：`模块 | 分数 | 需求描述（用户故事）`，列出本期 14 条故事。
  分数由老师评定，组内留空。
- 每个模块一个 sheet（`账号与权限`、`站点外壳`、`车型管理`、`官网浏览`、`选车辅助`），表头固定为
  `功能名称 | (空) | 测试用例名称 | 级别(0-5) | 测试步骤 | 预期结果 | 测试结果 | BugID`。
- `功能名称` 列填写用户故事全称（如 `US-CAR-12 车型参数管理`），同一故事的用例纵向合并单元格。

## 填写规则

| 列 | 要求 |
| -- | ---- |
| 测试用例名称 | 一句话说明验证点，如「参数代码重复（忽略大小写）校验」 |
| 级别(0-5) | 按老师定义：0 最高，本组约定 P0→0、P1→1、P2→2 |
| 测试步骤 | 编号步骤，写明点击/输入/请求内容 |
| 预期结果 | 可判定的结果；接口用例写状态码 + 错误码 |
| 测试结果 | 通过 / 不通过 / 阻塞 / 未执行，如实填写，不伪造通过 |
| BugID | 不通过时填 `BUG-<故事>-<序号>`，缺陷详情写在对应 md 记录里 |

约定：

- 预期结果只写**验收要点**，不写实现细节（例如写「缺失值渲染为 —」，不写组件名）。
- 接口用例必须覆盖成功路径、字段校验失败、资源不存在三类。
- 页面用例写清选择器无关的操作描述，便于别人手工复现。
- 未开发完的故事先占位，测试结果标记「阻塞」，不要留空。

## 提交方式

测试用例属于文档改动，同样走分支 + PR：

```bash
git checkout main && git pull
git checkout -b feature/test-cases-<你的名字>
# 编辑 docs/quality/test-cases/途越测试用例及跟踪.xlsx
git add docs/quality/test-cases
git commit -m "docs: 补充 US-XXX 测试用例"
git push -u origin feature/test-cases-<你的名字>
```

在 GitHub 开 PR，至少 1 人评审后合并。由于全组共用一个 xlsx，合并前先 `git pull` 并沟通，避免覆盖他人填写的内容。
