# 测试用例目录

小组按用户故事提交测试用例，统一放在本目录。格式用老师给的模板，**每人提交自己负责的那份**，不共用一个文件。

## 文件

| 文件 | 用途 |
| ---- | ---- |
| `_模板.xlsx` | 老师格式的空表：`需求列表` + 5 个模块 sheet 的表头。复制一份，改名为 `测试用例及跟踪-<你的名字>.xlsx` 再填 |
| `测试用例及跟踪-<姓名>.xlsx` | 个人提交件，只填自己负责的用户故事（已有：唐轩、糜昊廷） |

## xlsx 结构

- `需求列表` sheet：`模块 | 分数 | 需求描述（用户故事） | 测试人员`，列出本期 14 条故事，已填好模块与测试人。
  分数由老师评定，组内留空。
- 每个模块一个 sheet（`账号与权限`、`站点外壳`、`车型管理`、`官网浏览`、`选车辅助`），表头固定为
  `功能名称 | (空) | 测试用例名称 | 级别(0-5) | 测试步骤 | 预期结果 | 测试结果 | BugID`。
- `功能名称` 列填用户故事全称（如 `US-CAR-12 车型参数管理`），同一故事的用例纵向合并单元格。
- 只填自己负责故事的模块 sheet；不负责的模块 sheet 保持只有表头。

## 填写规则

| 列 | 要求 |
| -- | ---- |
| 测试用例名称 | 一句话说明验证点，如「参数代码重复（忽略大小写）校验」 |
| 级别(0-5) | 0 最高。本组约定 P0→0、P1→1、P2→2 |
| 测试步骤 | 编号步骤，写明点击/输入/请求内容 |
| 预期结果 | 可判定的结果；接口用例写状态码 + 错误码 |
| 测试结果 | 通过 / 不通过 / 阻塞 / 未执行，如实填写，不伪造通过 |
| BugID | 不通过时填 `BUG-<故事>-<序号>`，并在 GitHub 开 issue 描述复现步骤 |

约定：

- 预期结果只写**验收要点**，不写实现细节（例如写「缺失值渲染为 —」，不写组件名）。
- 接口用例必须覆盖成功路径、字段校验失败、资源不存在三类。
- 页面用例写清选择器无关的操作描述，便于别人手工复现。
- 未开发完的故事先不填，或填「阻塞」，不要留空。

## 提交方式

测试用例属于文档改动，同样走分支 + PR：

```bash
git checkout main && git pull
git checkout -b feature/test-cases-<你的名字>
cp docs/quality/test-cases/_模板.xlsx docs/quality/test-cases/测试用例及跟踪-<你的名字>.xlsx
# 打开自己那份，只填负责的故事
git add docs/quality/test-cases
git commit -m "docs: 补充 US-XXX 测试用例"
git push -u origin feature/test-cases-<你的名字>
```

在 GitHub 开 PR，至少 1 人评审后合并。每人一个文件，互不冲突，可以并行提交。
